Overview

Project Overview

Basil POS is an enterprise-grade restaurant Point of Sale and operations management application designed to handle high-frequency hospitality workflows. The platform unites floor ordering, table status management, kitchen order routing (KDS), split billing, custom tipping, hardware payment terminals, and ESC/POS thermal kitchen printing into a unified, crash-resilient mobile interface.

Product Context & Objectives

In busy dining environments, software failure or printer disconnects directly halt restaurant revenue. The goal was to build a low-latency, highly stable mobile POS solution with offline-tolerant order queuing, seamless payment terminal handshakes, and immediate ticket synchronization with kitchen display monitors.

System Architecture

Hardware & Software Integration Architecture

Peripheral Hardware Abstraction

POS environments require interfacing with legacy and modern peripherals simultaneously. An abstracted Device Driver Manager was created to handle connection drops, auto-reconnects, and buffer flushes without locking the UI thread.

Thermal receipt layouts were rendered using programmatic ESC/POS byte arrays, generating crisp tabular tickets with zero image rasterization delays.

Kitchen Order Flow

01 Server inputs order with modifiers at table terminal
02 Order payload dispatches to backend API with local cache fallback
03 KDS display syncs ticket; station thermal printer prints prep ticket
04 Cook bumps ticket → Server alerted of food readiness
Engineering Challenges

Key Challenges Solved

Challenge: Flaky Local Wi-Fi Interrupting Printing

Restaurant kitchens often suffer from localized network interference from stainless steel appliances and microwave units, causing socket timeouts during receipt printing.

Solution Implemented:

Built an in-memory persistent print queue that guarantees at-least-once delivery, automatically retrying disconnected printers and alerting managers if a printer remains offline.

Challenge: Complex Split-Check Billing States

Handling complex guest bill splits (by seat, by percentage, by individual item sharing) with mixed payment modes (cash + card + tip) creates deep transactional complexity.

Solution Implemented:

Modeled an immutable transaction ledger in state where split line items maintain parent references and balance reconciliation guards, preventing unpaid item checkout leaks.
